# DEC-20260827-009 — 阶段 4 计划、持久队列与备份库维护边界

**状态：** 已采纳

## 决定

阶段 4 以每个当前用户实例自己的 SQLite 控制库作为计划、批次、任务、尝试和租约的唯一状态来源。计划只保存当前租户中由用户显式选择的实例 ID；不保存、接收或推导其他用户 UID，也不根据后续发现的应用动态扩展目标。批次以 `tenant_uid + plan_id + scheduled_at` 去重，任务以 `batch_id + deploy_id` 去重，同一实例的活动任务由数据库约束和租约共同限制。

Worker 只能从持久化队列认领任务。认领时记录随机 lease token、worker ID、到期时间和心跳；进程重启后回收过期租约，并将可重试任务按既有退避策略重新排队。取消只影响当前租户任务，不能越过已经开始的源数据安全检查。备份引擎继续使用阶段 3 的只读 source resolver 和当前用户 document-root 存储边界。

备份库只读取当前用户 `MimiAppBakcup/<deploy_id>/<时间>/` 内由已完成 manifest 证明的快照。删除先改为待清理状态并安全移动到 `_trash/`；导出只能写入 `_restore_exports/`，拒绝 ZIP 路径穿越和符号链接。校验失败时暂停保留删除，并至少保留一份已校验快照。目录扫描与索引对账不读取 source 目录，也不扫描其他用户网盘。

## 后果

- 手动备份和计划备份使用同一持久化任务模型，但既有手动作业 API 保持兼容。
- 前端只能轮询或读取正式任务/批次/快照接口；阶段 4 不通过本地计时器伪造队列、重试或清理结果。
- 告警、通知、SSE、审计详情和完整中英文页面在阶段 5 提供；本阶段只保留稳定错误码和安全状态。
- 真实平台仍需验证多实例容器的后台自动启动、错过计划的补跑以及当前用户网盘路径。
