# DEC-20260830-013 — 游标分页与正式界面来源

**状态：** 已采纳；真实平台证据待补

## 决定

`designs/web.tsx` 是正式 Vite 界面的唯一视觉与页面结构来源。样式模板逐字迁移，不以新 CSS 修补交互、焦点、动画或点击面积。页面 JSX 仅为真实数据、双语、可用接口和分页进行必要调整。

`deployId` 是实例、计划目标、任务、快照和批量选择的唯一前端关联键。`appid` 仅用于展示，不能用于跨实例关联。

`/api/backups`、`/api/batches`、`/api/tasks`、`/api/alerts`、`/api/audit` 和 `/api/instances/{deployId}/backup-scope` 都使用不透明 `cursor`、`limit` 与 `nextCursor`。查询总是先按当前 tenant 限制：快照按完成时间和 ID 倒序，批次/任务/告警/审计按创建时间和 ID 倒序，范围目录按安全相对路径和类型升序。游标还会绑定当前 tenant、查询类型和已支持的筛选条件；任务保留 `status`、`batch_id`、`deploy_id`，告警保留 `status`。格式、查询范围或筛选条件不匹配的游标统一返回 `INVALID_CURSOR`。

## 后果

- 通过租户筛选、稳定排序和记录 ID 可以在插入新记录时继续向后分页，不使用 offset，也不暴露数据库排序值。
- 把旧游标带到其他租户、其他应用范围或不同筛选条件下会被拒绝，前端在筛选条件变化时从第一页重新读取。
- 所有新增数据库变化仅为索引；不迁移或改写业务记录。
- 范围目录的游标不放宽安全规则。范围保存和实际执行始终重新解析并验证相对路径。
- 计划列表不分页，以便推导应用的下次执行；其他长列表由服务端分页，前端不构造演示记录填充页面。
