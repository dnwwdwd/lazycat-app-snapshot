# DEC-20260827-008 — 手动 ZIP 快照使用受限后台作业和当前用户网盘原子提交

## 决定

阶段 3 的手动备份只接受当前已登录租户目录中的一个 `deploy_id`。服务在创建作业前再次读取实例记录、确认可备份状态，并对单实例目标要求 `sharedRiskAccepted=true`。不接受浏览器传入的用户 UID、owner UID、源路径、网盘路径或文件列表。

作业由每个备份应用实例内有界的后台执行器运行，同一 `deploy_id` 在作业结束前不能并发执行第二次手动备份。它重新解析固定 appvar 投影，执行完整预检；发现无数据、越界符号链接、特殊文件之外的阻断数据库或不稳定文件时不会把快照提交到备份库。

普通文件使用只读打开和流式 ZIP 写入。标准 SQLite 通过 `modernc.org/sqlite` 暴露的 SQLite Online Backup API 生成临时副本，执行 `quick_check` 后写入 ZIP；不复制原始 SQLite、WAL、SHM 或 journal 文件，也不因 SQLite 失败退回原始复制。

存储层只接收相对路径，并固定在当前用户 `/lzcapp/document/LazycatAppBackup` 根内。ZIP 先写入 `_partial/<job_id>/`，计算 SHA-256 后移入 `yyyyMMddTHHmmss.SSSZ/<deploy_id>/snapshot.zip`；外部 `manifest.json` 最后写入。没有完成外部 manifest 的目录不记录为快照。控制库保存租户绑定的作业与快照安全元数据，不保存源绝对路径、Token 或 Cookie。

阶段 3 不实现计划、批量任务、通用租约队列、重试、补跑、保留、删除、导出或 SSE。这些能力仍使用阶段 4 的数据模型和调度边界。

服务启动时会把上次进程中仍为 `QUEUED` 或 `RUNNING` 的手动作业标记为 `FAILED/BACKUP_INTERRUPTED`，并清理其内存实例锁。阶段 3 不尝试恢复或重放这类作业，避免把未完成的临时目录当成快照；可恢复租约和重试由阶段 4 的通用队列处理。

## 理由

这个边界能让用户从应用页实际生成可校验 ZIP，同时维持 POC 已验证的当前用户数据入口与只读规则。将任务执行范围限制为手动单实例，避免在调度、租约和保留策略尚未完成时承诺可恢复的通用队列行为。

## 本地实现状态

该边界已经实现并完成本地自动化验证。正式前端只展示当前用户的作业与快照安全元数据；应用页的立即备份请求和单实例确认均通过同源 API 进入服务端，不保留成功进度或快照的本地模拟逻辑。

## 验证边界

本地测试覆盖当前租户实例复核、单实例确认、阻断数据库、路径与符号链接拒绝、SQLite Online Backup 和 `quick_check`、ZIP 路径安全、manifest 最后提交、SHA-256 校验、失败不入库及快照租户隔离。真实平台仍需验证当前用户网盘写入和 A/B 用户快照隔离；本地文件系统测试不能替代该证据。
