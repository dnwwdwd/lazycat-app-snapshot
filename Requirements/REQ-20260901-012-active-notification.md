# REQ-20260901-012 — 任务终态双通道通知

**类型：** 功能改进
**状态：** 本地实现完成；真实平台和浏览器验证待执行
**来源：** 用户要求定时与手动备份的成功、失败结果同时发送懒猫平台消息和浏览器级通知。
**关联进度：** `Progress/PROG-REQ-20260901-012-active-notification.md`
**关联决定：** `Decisions/DEC-20260901-016-user-notify-message-service.md`

## 目标与验收

- 任务进入 `SUCCEEDED`、`SUCCEEDED_WITH_WARNINGS`、`FAILED` 或 `TIMED_OUT` 后，后端继续按当前租户的通知设置发送懒猫 `MessageService` 平台消息。
- 用户在设置页显式允许浏览器通知后，已打开的应用页面通过当前租户 SSE 收到同一任务终态时显示浏览器原生通知。
- 成功通知开关同时控制成功平台消息和浏览器通知；首次失败开关同时控制失败平台消息和浏览器通知。
- 浏览器未授权、不支持通知、页面关闭、SSE 中断或平台 `user.notify` 不可用时，备份、快照、站内告警和审计不得受影响。
- 首次打开页面不展示历史任务的浏览器通知；SSE 重连以事件游标补齐页面保持打开期间遗漏的任务终态。

## 范围与边界

- 浏览器通知使用标准 Web Notification API，不申请新的 LPK 权限，也不引入 Service Worker、Push 服务或外部通知服务。
- 浏览器通知只在应用页面保持打开、浏览器仍在运行且当前站点被授予权限时可用；不能替代已关闭页面或已退出浏览器时的后台推送。
- 事件与通知继续以当前认证租户为范围。事件正文只包含任务状态、任务/批次/应用实例标识符和当前账号可见的应用名称，不含源路径、Cookie、Token 或其他用户信息。
- 不增加跨用户参数、宿主机访问、高权限或目标应用写入。

## 验证

- 本地仅执行 Go 服务端编译、Vite 前端生产构建和差异检查，不新增或运行测试代码。
- 真实验证需要在懒猫设备中依次确认：授权浏览器通知、成功终态双通知、最终失败双通知、首次连接不重放历史弹窗、浏览器权限拒绝和 `user.notify` 缺失时的无阻断降级。
