# REQ-20260828-006 — 备份详情与表格视觉细化

**类型：** 功能与体验改进
**状态：** 本地实现完成；真实平台验证待执行
**来源：** 2026-08-28、2026-08-29 用户反馈（含存储页占用显示缺陷）
**进度记录：** `Progress/PROG-REQ-20260828-006-backup-library-detail-and-table-polish.md`

## 目标

让备份库、任务中心和存储维护页的信息层次清晰，同时保持当前产品的克制配色与租户边界。

## 验收条件

1. 备份库详情只读展示快照概况、备份范围、实际归档统计、创建时记录的完整性状态、云端目录和文件索引；范围、归档统计和完整性记录合并在一个信息区，文件索引默认只显示前一小段。打开详情不触发完整性校验，不提供导入、导出或移入回收站操作。
2. 云端目录显示 `MimiAppBakcup/` 下的完整相对路径。服务端返回目录状态，目录被删除时明确标记“目录已删除”，不把文件索引失败误报为校验失败。
3. 应用、计划、批次、任务和快照详情统一使用一个居中弹窗容器，不再使用右侧抽屉。批次详情将进度、成功和失败压缩为一行摘要，任务列表是主体；从应用、批次或快照切换到任务详情时复用同一弹窗并提供返回上一层，不叠加多个详情弹窗。
4. 备份计划将计划定义与最近执行分区；任务中心只突出运行中、排队中和失败任务，将当前或最近批次与历史任务分层展示。两页使用短标题和状态本身传达含义，不增加大段说明文字。
5. 设置页“错过后补跑”使用名称在左、开关在右的开关控件，并继续保存服务端实际使用的 `catchUp` 值。
6. 所有正式页面表格的表头使用独立底色、边界和至少 12px 的可读字号，列名不再使用过小的装饰性大写样式。
7. 存储页以 `archiveBytes / (archiveBytes + availableBytes)` 显示容量占比。非零但小于 0.1% 时明确显示“<0.1%”，进度条保留可见的最小填充；占用为零时才显示 0% 和空进度条。页面把已用空间、可用空间、快照数、最近校验、校验异常和部分写入收敛为主容量卡和紧凑状态行，不使用大面积空白色块。

## 边界与实现

- 新增的 `Snapshot.storageStatus` 只描述当前用户网盘目录是否可达（`AVAILABLE`、`MISSING`、`INACCESSIBLE`），不改变 ZIP 校验和存储维护 API。
- 本次存储页修复只使用既有 `StorageSummary.archiveBytes`、`availableBytes`、`snapshotCount`、`missingCount`、`partialCount` 和 `lastVerifiedAt`；不修改容量计算、接口、网盘目录或任何存储写入行为。
- 保持当前用户、当前实例、`appvar.other.read`、源数据只读和 `MimiAppBakcup` 写入边界；不添加恢复写入、跨用户目录或宿主机路径。
- 本地只执行 Go 服务端构建、OpenAPI 类型生成、Vite 构建和差异检查，不新增或运行测试代码。
- 任务详情的尝试列表在中文界面使用“执行记录”标题；仅调整展示文案，不改变 `task_attempts` 数据或接口。
- 所有正式页面容器统一使用可用内容区域 90% 的最大宽度；不改变页面路由、数据接口或移动端导航。
- 概览页指标卡统一为四列网格，卡片保持一致高度、内边距、圆角、图标底色和数值层级；窄屏按三列、两列和单列自适应。
