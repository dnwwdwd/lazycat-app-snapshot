# REQ-20260831-011 — 页面标识清理与应用重新检测反馈

**类型：** 缺陷修复 / 体验改进
**状态：** 本地实现完成；真实懒猫验证待执行
**来源：** 2026-08-31 用户反馈

## 目标

- 移除所有正式业务页标题中的 `MIMI APP BACKUP · V1` 重复眉题；语言仍只在设置页“外观”中修改。
- 单项与批量“重新检测”受理后提示“已提交，正在同步”，失败时沿用统一 API 错误提示。
- 应用目录同步状态在受理 API 返回前持久化为 `RUNNING`，使前端能持续读取本次异步探测结果。
- `PROBE_FAILED` 条目展示服务端探测失败码，区分已加载的检测失败与加载中的空数据状态。
- 任意应用的数据源未出现在已授权 appvar 投影中、投影不可见或读取被拒绝时，显示“系统或权限受限”，不再显示“需要重新检测”或 `PROBE_FAILED`。
- 受限扫描达到 100,000 个目录项时，使用 `SYSTEM_UNSUPPORTED/SOURCE_ENTRY_LIMIT_EXCEEDED`，不把这个确定的资源边界误报为 `PROBE_FAILED`。
- 对真实文件系统读取被拒绝的探测错误，保留稳定的权限原因码；未分类探测失败仍保留 `PROBE_FAILED`，避免把可重试的异常混同为平台限制。
- 首屏数据就绪不自动显示 toast；toast 只用于明确操作的反馈，语言代码不得作为提示文本保留在页面。

## 验收

1. 八个业务页面不再显示 `MIMI APP BACKUP · V1`；设置页保留唯一的语言选择控件。
2. 点击单项、批量重新检测或重新扫描全部后，在成功受理时显示短时站内提示，不把异步探测误报为完成。
3. `POST /api/instances/{deployId}/probe` 与 `POST /api/applications/sync` 返回后，下一次应用列表读取的同步状态为 `RUNNING` 或终态，不读回先前的 `IDLE`。
4. 检测仍失败时，应用列表能显示后端返回的 `probeErrorCode`；状态消失时表示新的探测已成功写入，而非前端本地隐藏。
5. 首屏完成后不出现持续的右上角 toast；所有留存 toast 在 3 秒后清除，`zh-CN` 和 `en-US` 不作为 toast 内容渲染。
6. Totoro 和其他数据源未出现在已授权 appvar 投影中、投影不可见或读取被拒绝的实例，在目录同步后为 `SYSTEM_UNSUPPORTED`，页面显示“系统或权限受限”，不进入“需要重新检测”筛选。
7. 普通 appvar 应用仍按既有路径探测；实际读取权限被拒绝时显示“系统或权限受限”，其他未分类探测异常才保留“需要重新检测”。
8. 任何应用扫描超过目录项上限时，持久化 `SYSTEM_UNSUPPORTED/SOURCE_ENTRY_LIMIT_EXCEEDED`；此规则不按应用 ID、名称或商店标签判断。

## 边界与验证

- LightOS 助手数据不通过宿主机路径、`other_uid`、高权限挂载或 `lightos.manage` 绕过隔离。等待官方按实例授权的只读数据接口后，才另行评估适配。
- 重新检测继续使用当前 tenant 的既有目录、源解析器和探测器；不传 `other_uid`，不读取宿主机路径，不写入目标应用数据。
- OpenAPI 状态枚举与已使用的 `SYSTEM_UNSUPPORTED` 对齐；不新增接口、备份队列、OIDC 或权限声明。
- 本地只执行 Go 编译、Vite 构建和 `git diff --check`；随后重新打包并检查 LPK。真实懒猫环境仍需确认 Totoro 状态、普通 appvar 应用回归、目录刷新和反馈时序。
